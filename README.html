Rust error tracing

Meet every ?

TraceHell creates an instrumented copy of a Rust workspace and reports the exact question-mark expression that passes an error back to its caller.

Quick start Commands How it works Source code

The idea

Errors leave a trail.

Rust's ? operator keeps error-handling code concise, but a chain of propagated errors can make the first failing expression harder to spot. TraceHell rewrites those expressions in a separate copy of the workspace so each propagated error prints useful context while the original source stays untouched. 

? src/parse.rs:42: file.read_to_string(&mut contents) -> Os { code: 2, kind: NotFound, ... }

Setup

Quick start

TraceHell requires Rust with Cargo and one supported terminal: Kitty, Alacritty, or GNOME Terminal.

# Install from a local checkout
cargo install --path .

# From the Rust project you want to inspect
cargo tracehell create my-trace

# Run a command inside the instrumented copy
cargo tracehell run my-trace cargo run

On first use, TraceHell asks which terminal to launch and stores the choice in ~/TraceHall_settings. Instrumented copies live under ~/.TraceHell.

CLI reference

Four commands, one workflow.

CommandPurpose
create <name> Copies the current Cargo workspace and instruments its Rust source files.
run <name> <command> Opens the named copy in the configured terminal and runs the supplied command.
delete <name> Removes the named copy from ~/.TraceHell.
help Prints usage, available commands, examples, and the installed version. The aliases -help, --help, and -h are also accepted.

Every command accepts a bare name, a single dash, or a double dash—for example, run, -run, and --run.

cargo tracehell create parser-debug
cargo tracehell --run parser-debug cargo test
cargo tracehell -delete parser-debug
cargo tracehell help

Under the hood

How it works

01 / COPY

Clone the workspace

Project files are copied into a named directory under ~/.TraceHell. Build output and Git metadata are skipped.

02 / REWRITE

Instrument each ?

Rust files are parsed with syn. Try expressions become matches that print context before returning an error.

03 / RUN

Launch the trace

The selected terminal opens in the copied workspace and runs the command you supplied, leaving the shell open afterward.

Details

What gets reported

When an instrumented expression returns Err, TraceHell writes four pieces of context to standard error:

Source file

The path produced by Rust's file!() macro.

Line number

The location of the generated trace point.

Expression and error

A colored ? marker, the expression as source text, and the error's debug representation.

Trace names must be a single path component. Before launching a command, the current command filter rejects text containing rm, dd, wipefs, or sudo.
